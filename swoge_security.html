SWOGE Security

Defensive bug bounty & OSINT — read-only, authorized targets only.

These tools only read: public OSINT, already-collected exposure data, on-chain contract source. No active scanning, no exploitation, no credential attacks. A target must be in a bug-bounty program scope, or you must tick the box that attests you are authorized to assess it. Ticking it does not grant permission — you are responsible.

Contract pre-audit

Paste Solidity source. A static assist (access control, reentrancy, rounding, oracle), precision-first — a lead to verify, never a verdict. Nothing leaves as an action.

Dependency vulnerabilities

Known CVEs for a package version, from OSV.dev (public database, like NVD). No target is contacted.

Targeted tools — authorization required

For the three below, either the target is in a program scope you enter, or you tick the attestation.

Authorized recon (passive)

Public OSINT on a domain or on-chain address — DNS, RDAP, certificate transparency, the target's own pages (robots.txt respected). Read-only.

Passive exposure (IP)

Open ports & known CVEs an IP already exposes, read from Shodan InternetDB — already collected, no packet is sent to the target. This is the safe stand-in for a port scan. It also guesses the device type (website, router, mail server, camera, PC, phone behind NAT…) from the passive data.

Dark-web monitoring (.onion)

Read a public .onion page to check your own exposure (your contract address, domain, leaked credentials). Read-only (GET). This is not a free-roam browser, and it is off unless a Tor daemon is configured server-side.

Not available here, by design: SQL injection, password cracking of others' hashes, port scanning that sends packets, or any active intrusion — no checkbox unlocks those.
